E5, E6-A, and E6-B represent the latest phase of experimentation on the SERA project-memory span extractor. The goal is a strictly extractive model under 500M parameters that identifies exact character-offset spans of user prompts containing persistent project memory information. The model must output BIO tags on a per-token basis, recover exact substrings via character offsets, and never hallucinate text that is not present in the input. Evaluation is prioritized in this order: unseen-vocabulary F1, context-reversal performance, exact span F1, random test F1, and inference cost.

E5 tested whether adding a linear-chain Conditional Random Field on top of BERT-medium would improve BIO sequence consistency. The architecture was INPUT TOKENS to BERT-medium to an emission layer to CRF to Viterbi decoding to BIO output. The CRF adds sequence-level transition constraints that prevent illegal sequences such as I-PROJECT_INFO appearing without a preceding B-PROJECT_INFO. The allowed transitions were O to O, O to B, B to O, B to B, B to I, I to O, I to B, and I to I. The model had 35M total parameters with 19.2M trainable plus 15 parameters in the CRF transition matrix. Training used 5000 subsampled examples, batch size 32, gradient accumulation 2, learning rate 3e-5, and 2 epochs. Training completed in 18.6 minutes.

The E5 results were striking and counterintuitive. On the full evaluation suite the CRF model achieved test F1 of 0.5710 with precision 0.7660 and recall 0.4551. This was substantially higher than E1 baseline test F1 of 0.5058. Context-positive F1 was 0.5867. However, unseen-vocabulary F1 collapsed to 0.4444, down from 0.7085 in E1. The CRF was extremely conservative. It achieved high precision by refusing to predict spans unless it was very confident, which crushed recall on unseen vocabulary. The model learned to be extremely selective about when it would emit a B tag, which helped on familiar patterns but destroyed generalization to novel technologies. Because unseen-vocabulary F1 is the primary evaluation metric, E5 was rejected as a candidate despite the impressive headline F1 number. The checkpoint was saved at checkpoints/experiment_e5_crf/ but E1 remained the operational best model.

Before E6, a full-data baseline was established by training BERT-medium on all 18,326 training examples without any subsampling. Previous experiments had used 5000-example subsamples due to CPU constraints. The full-data model achieved test F1 of 0.5143 and unseen-vocabulary F1 of 0.7248, both improvements over the subsampled E1 results. This became the new baseline against which E6 would be measured. The improvement from full-data training confirmed that subsampling was leaving performance on the table and that the model could benefit from seeing all available training signal.

E6 was designed as a controlled data-augmentation experiment targeting the model's primary weakness: false-positive extraction of task-description language. An error analysis was performed on the full-data baseline's predictions against the random test set, producing 22,448 false positives and 3,112 false negatives. The false positives were classified into categories. The largest category was DESCRIPTION_FRAGMENT at 18.5 percent, followed by COMMON_WORD at 9.2 percent, INPUT_OUTPUT_SPEC at 7.1 percent, FUNCTION_SIGNATURE at 5.8 percent, DATA_TYPE at 4.4 percent, CODE_SYNTAX at 3.8 percent, CODE_ANNOTATION at 3.5 percent, PUNCTUATION at 2.1 percent, ACTION_VERB at 1.8 percent, ADJECTIVE at 1.2 percent, BOOLEAN_NULL at 1.1 percent, TECHNOLOGY_WITHOUT_REQUIREMENT at 0.9 percent, NUMERIC_VALUE at 0.7 percent, and OTHER at 39.7 percent.

The augmentation generator was built as augmentation_v2.py, a 515-line module that produces three categories of synthetic training examples. Negative templates generate prompts that contain words the model was falsely extracting, such as "Create a function that processes data" or "The program should handle requests." These prompts have empty span lists, teaching the model that description language is not project-memory information. Positive contrasts generate prompts that include explicit technology requirements such as "Use Python for the backend" or "Implement with React." These have single-span annotations on the technology name, teaching the model the difference between describing what a function does and specifying which technology to use. Concise positives generate minimal prompts such as "Python backend" or "React API" with single-span annotations on the technology. The generator maintains a list of 158 positive technologies spanning languages, frameworks, databases, infrastructure, protocols, and libraries. It uses 30 negative templates with slot-filling for thing words, action words, type words, and output words. Every generated record is validated with a substring equality check that verifies each span's character offsets exactly reproduce the annotated text.

E6-A used 10 percent augmentation, generating 2,289 examples added to the 18,326 base training records for a total of 20,615. The augmented records were split into 763 negative templates, 763 positive contrasts, and 763 concise positives. Training was performed on the Oracle server, an aarch64 machine with 23GB RAM running CPU-only PyTorch. The training used batch size 8, gradient accumulation 8 for an effective batch of 64, learning rate 3e-5, 2 epochs, and max validation set of 300 examples. Training completed in 112.7 minutes. The best validation F1 was 0.5460, up from the full-data baseline of 0.5150.

E6-B used 20 percent augmentation. The augmentation generator had an infinite loop bug that caused it to hang when the target number of examples exceeded the template space. The bug was fixed by adding a max_attempts limit of three times the target for each category. With the fix, 20 percent target generated 3,667 unique examples, achieving an actual ratio of 16 percent because the template combinations were partially exhausted. The combined training set had 21,993 records. Training was performed locally on a 16-core, 15GB RAM machine with batch size 32, gradient accumulation 2 for an effective batch of 64, learning rate 3e-5, 2 epochs, and validation set of 300 examples. Training completed in 74.3 minutes. The best validation F1 was 0.5368.

Full evaluation on the same evaluation suite showed E6-A achieving test F1 of 0.4980 with precision 0.3384 and recall 0.9425, unseen-vocabulary F1 of 0.632, and context-positive F1 of 0.4875. E6-B achieved test F1 of 0.4883 with precision 0.3285 and recall 0.9511, unseen-vocabulary F1 of 0.597, and context-positive F1 of 0.4766. The full-data BIO baseline evaluated on the same suite achieved test F1 of 0.4791 with precision 0.3206 and recall 0.9471. E6-A outperformed both the baseline and E6-B on test F1, unseen-vocabulary F1, and context-positive F1. E6-B had marginally higher recall but at the cost of lower precision and lower F1 across all categories.

The conclusion is that 10 percent augmentation is optimal and more augmentation introduces noise. The template-generated examples at 20 percent ratio began to saturate the augmentation space, producing repetitive patterns that diluted the training signal rather than reinforcing it. E6-A is now the best model with 19.2M trainable parameters, 35M total, trained on 18,880 examples, and checkpointed at checkpoints/oracle_e6a/best/model.pt.

The codebase is organized under the extraction directory. The src/data/ directory contains alignment.py which builds BIO label sequences from character offsets and tokenization, dataset.py which wraps aligned records into PyTorch datasets with support for augmented negative examples via an is_augmented flag, augmentation.py which was the initial augmentation generator, augmentation_v2.py which is the enhanced generator with false-positive pattern targeting and substring validation, label_schema.py which defines the three-label BIO schema, pipeline.py which runs the full data pipeline, and splits.py which performs conversation-level train/val/test splitting. The src/models/ directory contains token_classifier.py which implements the BERT-medium plus linear projection plus softmax architecture and token_classifier_crf.py which adds a CRF layer with allowed BIO transitions. The src/training/ directory contains trainer.py which implements the full training loop with warmup, gradient accumulation, early stopping, class-weighted loss, gradient clipping, and checkpoint saving. The src/evaluation/ directory contains evaluator.py, build_eval_suite.py, build_hard_negatives.py, and baselines.py. The src/inference/ directory contains extractor.py for span recovery at inference time.

Training scripts are organized as individual files per experiment. train.py is the original configurable script. train_e3.py adds hard negative examples. train_e4.py implements BILOU labeling. train_e5.py adds the CRF layer. train_e6.py trains on augmented data. train_full_bio.py trains on the full dataset without subsampling. train_lightweight.py is the memory-optimized script with RAM monitoring and configurable batch size and gradient accumulation, used for both Oracle and local training.

The data pipeline produced 22,908 aligned records from 2,989 OASST and 19,919 AM-DeepSeek prompts with 76,005 extractive spans, split into 18,326 train, 2,291 validation, and 2,291 test at the conversation level. The evaluation suite contains five categories: random test with 2,291 examples, context reversal with 1,083 positive and 200 synthetic negative examples, unseen vocabulary with 6 unseen examples and 24 unseen technologies, cross-language with python, r, go, and javascript subsets, and concept holdout with kotlin as the held-out technology. All evaluation uses exact substring matching between predicted character offsets and gold spans, not token-level approximation.
